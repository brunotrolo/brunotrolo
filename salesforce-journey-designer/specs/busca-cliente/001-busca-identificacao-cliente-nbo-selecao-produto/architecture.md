# Architecture — `busca-cliente/001` — Busca e identificação de cliente com NBO e seleção de produto

> **Mapa de artefactos e conexões** (Princípio IX). Cada artefacto de `tasks.md` tem 1 linha aqui. Conexões são concretas e resolvíveis: `Chama` nomeia outro artefacto desta tabela, nunca "backend" vago. Contratos cross-domain aparecem como linhas `data/API` lidas por domínios consumidores. Protótipo `prototype/` (LWC real sobre SLDS2 real) **validado e aprovado 2026-09-06 (gate VIII)** — ver `prototype/README.md`.

## 3. Constraints de ordem de build (não óbvias na tabela)

1. **A01 → A05/A14 → A23 → A26–A28c → A29–A39 (incl. A35b/A35c) → A41 → A42 → A43–A50 (incl. A49b/A49c) → A53/A54 → A55**: campos External ID devem existir antes de `CustomerUpsertQueueable` ser testado; `ProductCatalog__mdt` antes de `c-product-hub`; `NamedCredential` antes de `HttpCalloutService`; LMS antes de qualquer LWC que `publish/subscribe`; LWCs antes de Jest que os testa; tudo antes de `package.xml`.
2. **B (A51/A52) antes de C**: `PS_BuscaCliente_Agente` deve existir antes de qualquer teste Apex/LWC que roda `System.runAs(userWithPS)` — caso contrário `INSUFFICIENT_ACCESS` mascara bugs reais.
3. **`A25 TriggerBypass__c = true` antes de `A37`**: Queueable `upsert` não pode disparar `AssetTriggerHandler` com lógica pesada nesta fase — bypass deve estar `true` no momento do primeiro `Database.upsert`.
4. **`A30 DocumentValidator` antes de `A36`**: `CustomerSearchController.identify()` chama `DocumentValidator.validate()` como guard — sem ele, teste de DV inválido (EL-01/02) falharia por callout desnecessário.
5. **`A37 CustomerUpsertQueueable` é async**: testes de upsert devem usar `Test.startTest()/stopTest()` para forçar `Queueable` + `EventBus` delivery; LWCs não podem depender de `Asset` já gravado — `c-customer-header-summary` lê DTO em memória (A44 Lê `DemographicDTO` memória, não `Asset` SOQL) para não flakyar quando Queueable ainda não rodou.
